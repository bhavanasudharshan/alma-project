# Coding-agent usage

**Tools.** Two Claude sessions with fixed roles. A planning session (Claude with Bhavana) acted as architect, product owner and QA lead: requirements traceability (`docs/REQUIREMENTS.md`), stage scope and acceptance criteria, one prompt per stage (`docs/agent/prompts/`), review of every report, and `NOTES.md`. Claude Code acted as implementer and tester only: it built each stage from its prompt, ran lint and tests before proposing a commit, and wrote the attribution trailers. It never chose architecture; disagreements came back as "Questions for the architect". Bhavana made every scope, stack and security decision, accepted each stage, ran the browser end-to-end, and controlled all commits.

**Delegated vs. kept.** Delegated: scaffolding, adapters, migrations, tests, frontend, bootstrap scripts, first drafts of docs — everything with a precise, verifiable spec. Kept: the stack, the layering and adapter boundaries, the state-machine and email-ordering decisions, the public-surface threat model, what to defer, and the commit/markdown gates. The split follows one rule: the agent is fastest where correctness can be checked mechanically; judgment stays with the human.

**Where the agent was wrong, and how it was caught.** The P0 backend report claimed the PENDING → REACHED_OUT transition was atomic. Rather than accept the assertion, the pre-commit audit prompt (`01b`, check 21) required firing ten parallel PATCH requests at one lead and pasting the output — repeated. The first run passed by luck; repeats returned 2, 2 and 4 simultaneous 200s: a check-then-act race with the guard in Python between SELECT and UPDATE, so two attorneys clicking together would both succeed. Fix (`98a9a0c`): the guard moved into the SQL predicate (`UPDATE … WHERE id=:id AND state=:current`, rowcount 0 → 409) with a concurrency test that runs five times. The same pattern later protected assignment. A second catch worth naming: Playwright found a server component importing a table from a `"use client"` module receiving a reference proxy, so the primary action button silently vanished while `tsc`, ESLint and the build stayed green (`df5de7c`). Sixteen caught mistakes are logged in `NOTES.md` with how each was found.

**Process.** Plan until every requirement maps to a stage and a test. One self-contained prompt per stage with a report-back section. Gates before any commit; red means stop. Proof-based audits (`01b`, `05`): command plus output, never claims. Commits only on explicit authorization; markdown only when named by path. Attribution is mechanical — `Agent`, `Author-mode`, `Review`, `Stage` trailers on every commit, plus `NOTES.md`.

Transcripts: `docs/agent/sessions/`. Prompts: `docs/agent/prompts/`.
